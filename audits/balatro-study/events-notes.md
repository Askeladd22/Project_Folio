# Event, motion, audio and canvas study

Evidence boundary: static, read-only inspection of Lua members inside the ZIP embedded in `S:/Hydra Games/Balatro/Balatro.exe`, using Python `zipfile` in memory. References below are **archive member paths and one-based member line numbers**, not repository source paths. No shipped source or assets were extracted into this repository. All descriptions are original paraphrases. No gameplay session, audio capture, latency test or GPU profile was performed; all times and coefficients are configured values, not measured outcomes.

## Event scheduling

- `engine/event.lua:5-45`: events default to immediate execution, with both blocking and blockable enabled. Delay defaults to zero. Events normally use the TOTAL clock; creation during pause selects REAL unless the caller supplies a clock. `pause_force` can also mark an event as created on pause. Ease events retain a reference to a mutable field and a target value; condition events default to equality against a requested stop value.
- `engine/event.lua:48-102`: first eligible handling normally starts the event's delay clock, rather than construction time. Events created outside pause are skipped while paused. An after event waits before invoking its callback; a before event invokes until completion, then remains until its delay expires. Immediate events have no time gate but still need callback completion. Conditions poll a callback. Thus returning false is meaningful: it keeps work pending, and a blocking event can retain a queue barrier.
- `engine/event.lua:58-85`: ease supports linear interpolation, a quadratic remaining-time curve and an elastic curve. The starting value is captured again when interpolation actually begins. Completion is declared on the first processing pass beyond the end time, so the nominal duration is not an exact callback timestamp. Avoid calling the quadratic mode a generic ease-in without specifying its use of remaining time.
- `engine/event.lua:109-130,171-195`: five named queues separate base, tutorial, unlock, achievement and other work. Append is the default; front insertion is explicit. Each queue resets its own blocked flag. A blocked event can be bypassed only by a non-blockable event. A blocking event sets the barrier for the current pass even if removed on that pass; this can separate successive blocking effects by processing passes. Queue traversal uses Lua `pairs`, so there is no explicit total ordering across queues.
- `engine/event.lua:117-119,171-175`: processing has a configured 1/60-second threshold, driven by accumulated update delta. This is not an independent 60 Hz worker. There is one processing pass per update call once eligible; no inner catch-up loop. Forced processing bypasses the threshold without advancing the last-processed timestamp. Consequently, 16.67 ms is a scheduling parameter, not measured jitter or guaranteed spacing.
- `engine/event.lua:133-168`: queue cleanup preserves events marked `no_delete`. This flag affects explicit clearing, not ordinary completion removal.

## Clock domains and orchestration

- `main.lua:69-82`: update delta is a weighted smoothing of the previous value and latest timer step (80/20), capped at 0.1 seconds. A fallback cap of 500 FPS controls a sleep budget; it does not establish achieved frame rate.
- `game.lua:2449-2469`: sound modulation and room/canvas motion run before REAL, REAL_SHADER, UPTIME and BACKGROUND advance. REAL is therefore accumulated smoothed delta, not direct wall time. Reduced motion pins REAL_SHADER to a constant, while BACKGROUND advances according to a separate spin amount.
- `game.lua:2484-2509`: pause zeroes the gameplay delta after the real-clock increment. TOTAL advances using gameplay speed, while event-manager polling uses the retained real delta. HAND_PLAYED and NEW_ROUND accumulate an acceleration term; after it exceeds 2 it adds to speed, with accumulator capped at 16. A configured delay on TOTAL therefore varies with settings, state and accumulated acceleration. Paused UI events can still progress on REAL.
- `game.lua:2612-2633`: sprite animation receives real delta times speed; transform movement receives real delta capped at 0.05; object update receives gameplay delta times speed. These are deliberately distinct timing paths. Claims that every animation uniformly speeds up with GAMESPEED would be wrong.

## Target transforms, elastic feedback and camera motion

- `engine/moveable.lua:250-275`: a juice impulse lasts 0.4 REAL-clock seconds, is disabled by reduced motion, replaces the current impulse record, and immediately compresses the visible scale. Default magnitude is 0.4. Scale oscillation uses angular coefficient 50.8 with cubic decay; rotation uses 40.8 with quadratic decay. These correspond mathematically to about 8.09 and 6.49 cycles/second, not measured visual frequencies. The base rotation sign can be chosen randomly. This is a decaying oscillatory impulse layered over normal transform following, not a fixed sequence of keyframes.
- `engine/moveable.lua:278-319`: per-frame stamps prevent duplicate motion work; non-pause-created objects stop moving during pause. Major objects drive their own motion, minor objects can update their parent first, and glued objects follow a separate attachment path. Stationary and alignment flags suppress some repeated minor calculations. These are observable implementation mechanisms, not quantified performance wins.
- `engine/moveable.lua:405-430,447-456`; `game.lua:2618-2627`: visible position follows target position through velocity smoothing, with a speed cap and near-target snapping. Scale includes drag (+0.1), hover (+0.05) and juice contributions when applicable. Rotation responds to horizontal motion as well as its target and impulse. Exponential coefficients are derived from real delta using rates 50 (position), 60 (scale) and 190 (rotation), while movement delta is separately capped. This is a responsive system with inertia; it should not be described as one global easing duration.
- `engine/moveable.lua:434-443`: width/height pinches move proportionally to target size at rate 8 per delta unit and clamp between zero and target size. An ideal full-size transition would take 0.125 simulation seconds under constant target and uninterrupted updates; actual rendered timing was not measured.
- `functions/common_events.lua:1127-1153`: room movement combines slow drift, faster jiggle and smoothed cursor offset. Jiggle decays with a factor based on five times delta. Reduced motion zeroes shake; cursor influence also has a thresholded screen-shake setting. Rumble combines impulse and jiggle, decays separately and respects the rumble toggle. This ties visual and tactile feedback to common state without proving synchronous hardware delivery.
- `functions/common_events.lua:1156-1160`: recurring card emphasis uses a REAL-clock, nonblocking and non-blockable after event, beginning after 0.1 by default and recurring at 0.8 while its predicate remains true. These are configured polling delays plus queue timing, not guaranteed physical intervals.

## Audio architecture and triggers

- `globals.lua:20`; `game.lua:79-105`: the inspected configuration enables a separate sound thread and starts `engine/sound_manager.lua` with request/load channels. A loading wait loop exists but is disabled by its condition. This is evidence of the configured path; no running thread was observed.
- `functions/misc_functions.lua:695-715`: play requests carry sound code, pitch, volume, state, pause-menu context and user sound settings. Muting and near-zero master volume prevent submission. Thread mode pushes a message; a fallback directly invokes playback. The included REAL timestamp is metadata here, not evidence of sample-accurate scheduled playback.
- `engine/sound_manager.lua:15-33,37-68`: startup creates OGG sources and briefly plays them silently before stopping. Music initially streams; other files initially use static sources. Playback searches for an idle source, otherwise creates another source; dynamically created music/ambient sources stream. Concurrent voices are therefore possible, but no voice cap or fixed complete pool is established by this code.
- `engine/sound_manager.lua:81-103,107-150`: music layers approach target volume using a delta-based factor of 3 and apply pitch modulation. SFX apply original pitch and user master/game-sound levels; splash-origin sounds get splash attenuation. Modulation releases stopped sources, and restart logic starts music layers at configured pitch 0.7 and volume 0.6. Do not describe crossfade as a fixed-duration transition or source reuse as a guarantee of allocation-free playback.
- `engine/sound_manager.lua:185-207`: the audio worker waits on channel demand and dispatches sound, stop, modulation and state-reset requests. Main-thread submission order can coordinate intentions, but queue delay, mixer buffering and audible onset are unknown.
- `functions/misc_functions.lua:719-778`: game state selects the desired music layer (packs/shop/boss/default), and game-over affects pitch. Ambient fire is driven by scoring flame intensity and change; an organ layer is driven by score relative to the blind requirement. Ambient volumes smooth toward their targets. This provides ongoing tension alongside discrete scoring sounds, rather than only isolated one-shot effects.

## Canvas composition

- `main.lua:324-387`: resizing preserves room proportions, recomputes room position, and recreates a readable full-window canvas with linear filtering. The inspected Windows high-DPI/AA setup branch is explicitly disabled. Do not claim active supersampling from the presence of AA code alone.
- `game.lua:2732-2743,2917-2967`: scene content is drawn to the main canvas; screenwipe and cursor occur before final composition. The main canvas is then drawn through the CRT shader to the AA target if present, otherwise the default target. A final AA draw exists conditionally. Uniforms include distortion, scale, feather, bloom, noise, scanlines, cursor position and elapsed time. Glitch intensity is explicitly zero at this call site. Room jiggle changes scene transforms; final CRT composition is a separate stage.

## Transferable design deductions (not copied implementation)

1. Separate authoritative game progression, queue choreography, transform settling and audio rendering. Give every effect a named clock and explicit pause behavior.
2. Use completion-driven barriers for readable effect sequences, with opt-in independent cosmetic work. Specify ordering between tracks if deterministic composition matters.
3. Combine a short impulse with continuous target following so objects retain spatial continuity while reacting. Provide reduced-motion equivalents rather than making motion the only signal.
4. Submit sound at the same semantic event as the visual impulse, then measure actual synchronization. Background intensity can follow scoring state independently.
5. Treat postprocessing as a final presentation pass. Measure its GPU cost at target resolutions; static canvas/shader code cannot establish frame-time budget.

Unknowns: achieved FPS, CPU/GPU costs, event jitter, thread backlog, audible latency, input-to-photon latency, platform-specific runtime behavior and subjective readability. No such metrics can be inferred from constants, comments or architecture alone.
